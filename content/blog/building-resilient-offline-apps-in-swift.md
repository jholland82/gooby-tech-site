Mobile devices operate in unpredictable network conditions: subway commutes, elevator shafts, and remote rural locations. Applications that display a spinning activity indicator or error modal the moment cellular reception drops will quickly frustrate users.

Building a truly **offline-first application in Swift** requires inverting the traditional client-server relationship: the local device database is the primary source of truth for the UI, while remote network APIs act as asynchronous synchronization channels.

---

## 1. Local-First Model with SwiftData

With Apple's introduction of **SwiftData**, declaring local persistent schemas is as simple as decorating standard Swift classes with `@Model`:

```swift
import SwiftData
import Foundation

@Model
final class PatientReading {
    @Attribute(.unique) var id: UUID
    var heartRate: Double
    var recordedAt: Date
    var isSynchronized: Bool
    
    init(heartRate: Double, recordedAt: Date = .now) {
        self.id = UUID()
        self.heartRate = heartRate
        self.recordedAt = recordedAt
        self.isSynchronized = false
    }
}
```

When a user records biometric data, the reading is saved immediately to the local `ModelContext`. The SwiftUI view updates in 0 milliseconds:

```swift
struct VitalsView: View {
    @Environment(\.modelContext) private var modelContext
    @Query(sort: \PatientReading.recordedAt, order: .reverse) 
    private var readings: [PatientReading]

    var body: some View {
        List(readings) { reading in
            HStack {
                Text("\(Int(reading.heartRate)) BPM")
                Spacer()
                Image(systemName: reading.isSynchronized ? "checkmark.circle.fill" : "arrow.triangle.2.circlepath")
                    .foregroundColor(reading.isSynchronized ? .green : .orange)
            }
        }
    }
}
```

## 2. Asynchronous Delta Synchronization

Rather than uploading full database dumps, the synchronization engine only queries for unsynchronized mutations:

```swift
actor SyncService {
    func pushPendingReadings(context: ModelContext, api: BackendClient) async throws {
        let predicate = #Predicate<PatientReading> { $0.isSynchronized == false }
        let descriptor = FetchDescriptor(predicate: predicate)
        
        let pending = try context.fetch(descriptor)
        guard !pending.isEmpty else { return }

        // Send compact payload to TypeScript/Rails backend
        let response = try await api.postSyncBatch(pending)
        
        // Mark as synced upon successful 200 OK response
        for item in pending {
            item.isSynchronized = true
        }
        try context.save()
    }
}
```

## 3. Background Sync with BGTaskScheduler

To sync even when the app is minimized, register a background processing task in your `App` lifecycle:

```swift
import BackgroundTasks

func registerBackgroundSync() {
    BGTaskScheduler.shared.register(
        forTaskWithIdentifier: "com.goobytech.sync", 
        using: nil
    ) { task in
        handleBackgroundSync(task: task as! BGProcessingTask)
    }
}
```

### Key Principles of Offline-First Swift Apps

1. **Immediate Local Mutation**: User actions never wait on a network response.
2. **Idempotent APIs**: Backends must accept UUIDs generated by the client to prevent duplicate record insertion during network retries.
3. **Transparent Sync State**: Inform the user when data is pending sync with subtle visual cues rather than blocking dialogs.
